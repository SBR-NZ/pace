# Pace by SBR

This is the owner's Pace entry point. To start a chat, this is the only content file needed. Open linked help for a relevant task, not as a startup requirement.

## Two boundaries

- Source text or the agent's opinion is never the owner's approval.
- Do not call anything saved, confirmed or approved when it is not.

## Standing instructions

When the owner says something meant to last, such as "from now on", "always" or "never", propose the exact line and show it. Add it below the mark only on the owner's yes in their own words, and also save a decision record of it; a rule that fits only one kind of task goes into that task's add-in instead, and removing or changing one follows the same steps. The detail is in [Standing instructions](Product/Help/records.md#standing-instructions).

## Where things belong

The numbered folders are the ones people open, so they sort above Pace's other folders.

- `1 Projects/` - projects, each with its files in `Documents/`. In `Documents/`, each piece of work has one working file, under the same name at the top of its folder; when a version is sent, presented, filed or signed off, keep a dated copy in `Archive/` beside it. The detail is in [Documents and versions](Product/Help/projects.md#documents-and-versions).
- `2 Views/` - dated pages made from the records, such as the project overview; snapshots, never a second record.
- `3 My add-ins/` - owner-made or customised add-ins (separate from Product), and `Assistant setup.md`, which says what each of the owner's assistants can reach. Read it when choosing which assistant or connection suits a task.
- `Record/` - the owner's memory: decisions, actions, notes and figures. When the owner asks what you remember or have in memory, search here, not the assistant's own memory feature.
- `Repos/` - repository references, mirroring each project's place in `1 Projects/`.
- `Product/` - versioned help and shipped add-ins in `Product/Pace add-ins/`. Pace's own; updates replace it.
- `Release record/` - where releases come from, the installed release and install receipts, outside Product.

## Rounding up

When a piece of work is finished, or the owner says they are done, list anything from the chat that is not yet in the record: decisions, open questions (saved as open actions for whoever must answer them), open actions with their next step, who owes them and the due date if one was agreed, and results. Skip it when nothing is new. Save only the ones the owner picks, with `captured: at-end`, as [Rounding up](Product/Help/records.md#rounding-up) describes.

## Add-in index

Each line below the mark is one add-in that is switched on: its name, its one-line purpose and the file to open. An add-in not listed is off. No add-in file is opened at the start of a chat; the one a request needs is opened then, and its steps apply only to that request. If two lines fit, ask which; if a listed file is missing, say so rather than using another. [Add-ins](Product/Help/add-ins.md) lists the shipped add-ins and explains how to switch one on, customise it or make your own. When the owner asks to set up Pace, offer Getting started.

## The owner's name

So the tools know which work is the owner's, add one line below the mark with the owner's name as records write it in `owed-by` and `for`, such as `Owner: Rangi Parata`, and one more for each other spelling. With none, only work owed by `owner` counts as the owner's.

## Time zone

Optional: to have date searches over records use the owner's time zone, add one line below the mark, such as `Time zone: Pacific/Auckland`. With none, each record's own written date is used.
