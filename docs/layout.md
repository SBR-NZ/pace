# Where Pace files live

`PACE/` is the folder you copy, not an owner's working folder. Use `python3 get-pace.py --to <place>` to put the newest released copy in a place you choose outside this repository. Keep that copy's `Pace.md` under that person's control. Only `Pace.md` is read to start a chat; linked help is opened when relevant.

| Need | Path in PACE | Ownership |
| --- | --- | --- |
| Chat entry point and add-in index | `PACE/Pace.md` | Owner's lines below each mark, never changed by updates; Pace's own parts kept current by updates while the owner has not changed them (`Product/Help/updates.md`) |
| Versioned Product and core help | `PACE/Product/` (`Help/` for help, `Tools/` for the record tool, updater and overview tool, `LICENSE.md` for the licence) | Shipped Product; this is the canonical Product source in the repo |
| Shipped add-ins | `PACE/Product/Pace add-ins/` | Product; one folder per add-in with its `ADD-IN.md` and optional host launchers (Project overview also has its page template), all off until listed in `Pace.md` |
| Records | `PACE/Record/` | Owner; one new file per record in format record-1 (`Product/Help/record-format.md`), never edited |
| Projects | `PACE/1 Projects/` | Owner; project folders, each inside its parent's folder at any depth (usually `<parent project>/<project>/`), each with a `Pace project.md` holding its stable id and a `Documents/` folder, where each piece of work has one working file and an `Archive/` of the dated versions that went out (`Product/Help/projects.md`) |
| Repository references | `PACE/Repos/` | Owner; one home reference under the project's own place, such as `<parent project>/<project>/<repo>/` (or `<project>/<repo>/` for a standalone project), tied to the stable project id; explicit cross-project links for shared repos (`Product/Help/repositories.md`) |
| Optional dated views | `PACE/2 Views/` | Owner; dated pages over `Record/`, never a second source of decisions or job state (`Product/Help/hosts-and-views.md`) |
| Owner-made or customised add-ins | `PACE/3 My add-ins/` | Owner; protected from Product replacement; a customised copy named in the `Pace.md` index is used in place of the shipped one. An older folder may keep them in `Pace/Add-ins/My add-ins/`, which updates also list and protect but never move (`Product/Help/add-ins.md`) |
| Release and installation record | `PACE/Release record/` | Owner or client IT; **outside Product**; `get-pace.py` writes `Installed release.md`, noting where releases come from and the installed release; updates add to it, add install receipts, install records and owner go-aheads here, and never change earlier ones (see `docs/updates.md`) |

A standalone project need not have a client parent; it sits directly in `1 Projects/`. A project can have projects of its own at any depth; long folder names deep down can push file paths past what Excel opens, as projects help describes. No owner project, record, repository reference, dated view, customised add-in or release receipt has been created in PACE; shipped add-ins are present but off by default. The `.gitkeep` markers exist solely to retain empty directories in git, not as data. `.gitignore` discourages accidental commits of files put in the owner-data folders, but is not access control; keep live folders outside the clone.

The repository also has `example/`, a separate illustration filled with entirely invented work (not for real use), `docs/` for explanations, `tests/` for invented-data checks, `VERSION` for `MAJOR.MINOR.PATCH`, and `CHANGELOG.md` for version history. Records, projects and exact-act confirmations have help and a standard-library record tool; shipped add-ins and the Product updater are present. The optional client decision reference is a separate record-1 kind in `Record/`, never a live connector. For a local install, the updater can prepare a precise proposal under `Release record/Proposals/` and check its current exact-act confirmation in `Record/`; the simple go-ahead route in `Release record/Go-aheads/` remains separate and is not itself a confirmation. Optional views are described in `PACE/Product/Help/hosts-and-views.md`. Host pointers in `PACE/AGENTS.md`, `PACE/CLAUDE.md` and `PACE/.github/copilot-instructions.md` only direct a host to `Pace.md`; they do not add another rulebook.
